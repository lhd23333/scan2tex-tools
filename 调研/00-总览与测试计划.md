# 影印书处理：工具清单总览与测试计划

> 2026-10-07 ｜ 两份调研全文：`工具清单-图像篇.md`、`工具清单-OCR篇.md`
> 本机环境：Windows 11 + RTX 5060 Laptop (8GB, sm_120) + Python 3.12；**MinerU 4.0.10 已本地部署**（服务 127.0.0.1:15980，需 `mineru.exe server start`）

## 一、推荐工具箱（按测试优先级）

### 第一梯队（先测这四个）

| 工具 | 角色 | 获取方式 | 关键事实 |
|---|---|---|---|
| **MinerU 4.x**（已部署） | OCR/公式识别主力 | 本机 `mineru.exe`，standard 档 | 中文最强；官方支持 8GB+Windows；输出 Markdown + JSON（公式为 LaTeX） |
| **ScanTailor Advanced** | 图像增强主力 | GitHub `ScanTailor-Advanced/scantailor-advanced` 的 **v1.1.1 x64 zip** | 分页/纠斜/裁边/二值化/去斑，整书批处理，免 Python；有中文语言包 |
| **Real-ESRGAN-ncnn-vulkan + SourceBook 模型** | 低清书超分 | ncnn 命令行包解压即用 + `tumuyan/SourceBook-Dataset` Release 的 Win64 ncnn 包 | **免 Python/免 CUDA**；SourceBook 是中文书籍专用 2x 模型，比通用模型对文字安全 |
| **Pix2Text**（或 PP-FormulaNet_plus-L） | 公式复核兜底 | `pip install pix2text` | 中文公式专项，用于 MinerU 输出有疑问的公式块重新识别 |

### 第二梯队（按需）

| 工具 | 用途 | 代价 |
|---|---|---|
| marker 2.0 | 公式质量榜单更高（arXiv math 83.9） | Windows 需 WSL2/Docker，部署门槛高 |
| DocRes / Doctra | 书页弯曲、阴影严重时 | DocRes 依赖钉死旧版需大改；Doctra 是 pip 装封装 |
| DN_SuperBook_PDF_Converter | Windows 一站式增强+OCR | 892★，但文档是日文 |
| OCRmyPDF | 只想要"可搜索 PDF"（不改外观） | 不产出公式/LaTeX |
| Umi-OCR | 中文离线 OCR 桌面版 | 不产出公式 |

### 明确不推荐
- **olmOCR**：硬编码 15GB 显存检查，8GB 跑不了（别被榜单分数吸引）
- **nougat**：无中文支持 + 已停更
- **texify**：已归档
- **Real-ESRGAN 通用模型直接处理文字**：会幻觉笔画
- **自适应阈值直接用在透印书上**：会强化透印（本项目已实验证实，见 README）
- **"BookOCR / Book-Cleaner"**：不存在（Gemini 编造）

## 二、按书分级的处理路径

| 书 | 图像现状 | 建议路径 |
|---|---|---|
| 数字设计 RISC-V | 198 DPI，图够好 | **直接 MinerU 重 OCR**（不做图像处理） |
| 模拟和数字电子电路 | 300 DPI 二值，图够好 | 同上 |
| 微电子学（150 DPI 彩扫） | 有灰底 | ScanTailor（二值化/去斑）→ MinerU |
| 算法导论 | 300 DPI 缩印小页 | 先最小裁剪留白 → MinerU 试；不行再 2x 超分 |
| 算法概论（96 DPI+透印） | 最差 | 背景除法预处理（本项目脚本）或 ScanTailor → SourceBook 2x → MinerU |

## 三、测试计划（建议）

### 测试素材
`调研/preview/` 已有每本书第 100 页渲染样本（PNG），可直接用于对比测试。
建议每本书选 3 类页面：纯文字页、公式密集页、图表页。

### 测试项（按顺序）
1. **MinerU 基线**：`数字设计` 抽 5-10 页 → Markdown，人工对照原文统计：汉字准确率 / 公式正确率 / 版面
2. **MinerU 最差素材**：`算法概论` 同几页 → 对比基线（验证低质扫描的衰减程度）
3. **增强前后对比**：`算法概论` 页面 → 背景除法预处理（`调研/baseline_enhance.py` 方法 D）→ 再 MinerU，对比 OCR 正确率是否提升
4. **ScanTailor 试用**：整章走一遍分页/纠斜/二值化/去斑，评估产出质量与工作量
5. **（可选）超分救赎**：96 DPI 页 → SourceBook 2x → MinerU，验证超分是否提升识别率

### 记录模板（结果落盘到 `调研/测试记录.md`）
```
## 测试 N：<工具> × <书> × <页码>
- 输入: 文件路径 / 预处理命令
- 命令: 完整可复现命令
- 耗时: X 秒/页
- 输出: 产物路径
- 汉字准确率: 抽查 3 段，X/3 无错
- 公式正确率: 抽查 5 个公式，X/5 正确
- 版面: 阅读顺序/标题层级/图表 是否正常
- 结论: 一句
```

### 评分口径
- 汉字准确率：抽查段落与原文逐字对比（允许 1-2 个错别字/段）
- 公式正确率：LaTeX 能否编译 + 符号语义是否正确（重点看下标、矩阵、分式）
- 可用性：中文必须能用 ctex/xelatex 编译

## 四、预期管理（重要）

1. **"整书一键出 tex"不存在**（2026-10 没有开源项目能做到）。现实路径：
   工具出 Markdown（公式内嵌 LaTeX）→ 自写拼装脚本（ctex preamble）→ xelatex 编译。
2. 公式识别即使是最好的工具也有错误率，**人工/LLM 校对是必经环节**；96 DPI 那本书尤其低。
3. **视觉清晰化（看）和文本还原（读）是两件事**：
   - 只要"看着清晰"：ScanTailor/背景除法就够了，成熟可靠
   - 要"可选中 + 公式 LaTeX"：必须走 OCR 链
   - 两个目标可以分开交付：清晰版 PDF（图像处理）+ Markdown/LaTeX 版（OCR）

## 五、环境红线（踩坑预告）

- RTX 5060 = sm_120：任何 PyTorch 项目必须 `torch >= 2.7 + cu128`，网上老教程（cu113/cu118）照抄必崩
- 优先选免 Python 工具（ScanTailor / ncnn-vulkan 系）绕开 CUDA 版本地狱
- `cv2.imwrite` 中文路径静默失败：统一用 `imencode + tofile`（本项目脚本已处理）
- MinerU 服务不常驻：重启电脑后需 `mineru.exe server start`
