## 一、结论先行

### 1.1 先反驳一个前提：对黑白线稿，"矢量化"多半不是你要的答案

需求写成"位图 → 矢量/代码"，拆开看其实是三件不同的事：

| 真实需求 | 正确解法 | 矢量化是必需的吗 |
|---|---|---|
| 重排进 LaTeX 时**不糊** | 二值化清洗 + 矢量化 → **回吐成单文件 PDF** | 需要矢量中转，但**不需要 TikZ** |
| 要**能改图**（改文字/改走线/配色） | 语义重画（schemdraw / circuitikz / WaveDrom / TikZ） | 矢量化只是参考底图 |
| 曲线图 → 数据 + 绘图代码 | WebPlotDigitizer 取点 → pgfplots | 与矢量化无关 |

理由（本次调研最重要的判断）：

1. **对二值线稿，"糊"的成因是抗锯齿 + 扫描灰阶 + 透印残影，不是分辨率不足。** 198 DPI 下一根 2 px 宽的线信息量足够；放大到 600 DPI 后变糊，是双三次插值把硬边缘抹成灰带。**矢量化 → 高分辨率重新光栅化 → 边缘重新变硬**，效果远好于任何插值，也远好于 AI 超分（AI 超分会"编造"边缘，在工程图上等于伪造线宽和节点位置）。
2. **已验证过的「背景估计除法 + 全局 OTSU」正是这条链路的正确前置步骤**（见 README 基线实验）。矢量化只是把它后面接上"取轮廓 → 高分辨率重绘"。
3. **通用位图追踪（potrace）输出"轮廓填充"而不是"线条"。** 一根线会变成闭合细长多边形（双线），节点数翻倍，边缘带扫描抖动，且**文字会变成轮廓路径**（不可编辑、无法换成中文衬线字体）。直接 `potrace → svg2tikz → TikZ` 得到的代码通常几万行、编译变慢、且几乎不会去编辑——投入产出比很差。
4. **"透印"问题会被矢量化放大**：透印残影在二值化后若没被吃掉，potrace 会**忠实地把它矢量化成细实线**，比原扫描件更显眼。所以矢量化前阈值要偏保守（宁可少一笔，不要多一条幽灵线）。

### 1.2 推荐路线（三档，按投入产出排序）

**主线 —「矢量中转、不做 TikZ」（覆盖 90%+ 的图，纯脚本可批量）**

```
MinerU 导出的 PNG
  → OpenCV 背景估计除法 + 全局 OTSU（已有方案）→ 去小连通域
  → mkbitmap（potrace 自带，灰度平滑 + 放大 + 阈值）
  → potrace -b pdf  ← 关键：直接吐 PDF，不吐 TikZ
  → \includegraphics{fig.pdf}
```

- 得到**真矢量、无限缩放、pdflatex/xelatex 原生支持**的插图，边缘锐利、线宽均匀。
- 两条命令批量跑，无需 Inkscape、无需 svg2tikz、无需改 LaTeX 工作流。
- **代价**：文字仍是轮廓（改不了字、换不了字体），线条保留扫描抖动（不会自动变横平竖直）。

**支线 —「真·代码化」（只对个别必须改的图）**

```
SVG（potrace 或 vtracer 出）→ Inkscape「路径 → 简化」降节点 → svg2tikz → TikZ
```

svg2tikz 是这条路上唯一成熟、且当前极其活跃的工具。必须先降节点，否则 TikZ 会爆炸。

**高价值路线 —「语义重画」（挑 10–30 张最关键的图，质量天花板）**

| 图类型 | 工具 | 成本 |
|---|---|---|
| 时序图 | **WaveDrom**（JSON → SVG） | 每张 5–10 分钟 |
| 电路图 | **schemdraw**（Python → SVG）/ **circuitikz**（LaTeX） | 每张 15–30 分钟 |
| 逻辑框图 | TikZ + positioning / mermaid | 每张 10–20 分钟 |
| 真值表 | LaTeX tabular（MinerU 已能识别表格） | 每张 3 分钟 |
| 曲线图 | **WebPlotDigitizer** 取点 → CSV → pgfplots | 每张 10 分钟 |

### 1.3 诚实预期

**能做到**
- 198 DPI → 等效 600–1200 DPI，肉眼"糊→锐"，且是**真矢量**（放大到海报尺寸也不糊）
- 全程脚本化，100+ 张图批量跑完在分钟级
- 阈值/参数单点可调，返工成本极低

**做不到**
- 文字不会变成可编辑文本（矢量追踪出来的是轮廓）。只有"重画"或"在 TikZ 里叠 LaTeX 节点后用 textext/手工定位"两条路。
- 线条不会自动"拉直"。追踪忠实保留扫描抖动，横线会有 ±1–2 px 起伏。
- 电路图不会变成网表。**开源界没有可用的"印刷电路图 → 语义网表"工具**（详见方向 B）。
- 全自动 AI 出 TikZ：DeTikZify 最接近，但 8 GB 显存跑 8B 需量化，且它是拿 arXiv 论文图训练的，对 198 DPI 扫描的教材电路图泛化能力未验证 [待验证]。

## 四、方向 C：线稿专用超分/增强 —— 与矢量化路线的对比

### 4.1 核心判断：**对二值线稿，别用 AI 超分**

| 维度 | AI 超分 | 二值化 + 矢量化重采样 |
|---|---|---|
| 边缘 | 模型"猜"出来的，可能引入振铃/纹理/伪线 | 从像素几何重建，边缘硬且位置忠实 |
| 线宽 | 可能被改变（模型倾向美化） | 严格保持 |
| 透印残影 | 可能被"补全"成实线 | 二值化阶段可调阈值压掉 |
| 风险 | 不可解释、不可控 | 参数透明、可返工 |
| 适用 | **灰度连续调**（曲线图、照片、阴影） | **黑白线稿**（电路图、时序图、框图） |

**所以：电路图/时序图/框图 → 走矢量化（方向 A）；曲线图/灰度图 → 才考虑超分。**

## 五、方向 D：端到端"图像 → LaTeX 图形"的现成管线

### 5.1 明确结论：**不存在**成熟的"图片 → TikZ 一条命令"开源项目

svg2tikz 官方文档明确写了这条边界：**栅格图必须先被 trace 成 SVG**，它只负责 SVG→TikZ 的后半段 [已验证]。最接近端到端的是 **DeTikZify**（研究模型，非生产工具）。

## 六、推荐管线（命令级）

### 阶段 1：线稿高清化 → 单文件 PDF（主线，批量）

**安装**：potrace（`scoop install main/potrace`，含 `potrace.exe` + `mkbitmap.exe`）。无需 Inkscape、无需 Python 包。

```powershell
# 前置：背景估计除法 + 全局 OTSU 出 8bit 灰度（OpenCV 脚本已有；干净插图可跳过直接喂）
# 关键技巧1：mkbitmap 的 -s 在二值化之前先平滑放大，消除阶梯状锯齿
# 关键技巧2：potrace 直接输出 PDF，不进 LaTeX 转换链
mkbitmap -f 4 -s 3 -t 0.45 in.png -o tmp.pbm
potrace tmp.pbm -b pdf -o fig.pdf --turdsize 3 --alphamax 1.0 --opttolerance 0.2 --longcurve
```

参数含义与调参指南：
- `-t 0.45`（**阈值，最关键**）：**调高**（0.5–0.55）能吃掉透印残影，代价是细线可能断；透印是主要矛盾时从 0.5 起试。
- `-f 4`：高斯滤波半径，压扫描噪点。
- `-s 3`：二值化前放大 3 倍 → 抗锯齿。**这是"让线变锐"的核心**。
- `--turdsize 3`：丢掉面积 ≤3 px 的斑点。
- `--alphamax 1.0`：角点阈值。工程图建议 0.8–1.0（太小保留毛刺，太大会把直角磨圆）。
- `--opttolerance 0.2`：曲线拟合容差。调大 → 节点少、文件小、但更"圆滑偏离"。

LaTeX 侧：`\includegraphics[width=\linewidth]{fig.pdf}`，pdflatex/xelatex 原生支持，**零额外宏包**。

**降级方案**（PDF 体积不可接受时）：改出 SVG，Inkscape 渲染回 1200 DPI PNG。

### 阶段 2：需要改的图 → TikZ（支线，逐张）

```powershell
potrace tmp.pbm -b svg -o fig.svg --turdsize 3 --alphamax 1.0 --opttolerance 0.3
# Inkscape：路径 → 简化，节点砍掉 60-90%（不做这步 TikZ 会爆炸）
inkscape fig.svg --actions="select-all;path-simplify;export-filename:fig_s.svg;export-do"
pip install svg2tikz
svg2tikz fig_s.svg --output fig.tex --codeoutput figonly --round-number 2 --noreversey --markings ignore
```

> `--round-number 2`（默认 4）能显著缩短输出；`--markings ignore` 关掉箭头识别（追踪路径上基本是误判）。svg2tikz 限制：渐变/滤镜类 SVG 特性支持有限。

### 阶段 3：曲线图 → 数据 + pgfplots（逐张）

1. WebPlotDigitizer（可离线）打开 PNG → 标定坐标轴 → 取点 → 导出 CSV
2. 写可重跑脚本（matplotlib 或 pgfplots）读 CSV 出图
3. **保留 CSV + 脚本**（结果落盘规范）

### 阶段 4：真值表 / 时序图 / 电路图 → 直接写代码

- 真值表：MinerU 已识别表格结构 → LaTeX `tabular`
- 时序图：WaveDrom JSON
- 电路图：schemdraw（Python）或 circuitikz（LaTeX）
- 框图：TikZ / mermaid

### 可选：AI 辅助生成 TikZ（探索性）

把「原图 PNG + 矢量化 SVG 底图」喂给多模态 LLM 要求输出可编译 TikZ，再用 dvisvgm/TikZJax 渲染回 PNG 与原图**逐像素比对**，迭代 2–3 轮（DeTikZify 论文的 render-and-compare 思路）。本地 8 GB 跑不动 8B 模型，用 API 更实际。

## 七、做不到的部分（诚实清单）

| 做不到 | 原因 | 缓解 |
|---|---|---|
| **文字变成可编辑文本** | 所有矢量化工具输出的是轮廓路径 | 只能重画；或 TikZ 层叠 LaTeX 节点 |
| **线条自动"横平竖直"** | 追踪忠实保留扫描抖动（±1–2 px） | Inkscape 里吸附/重画；或接受抖动 |
| **电路图 → 语义网表** | 开源界无可用的印刷电路图识别工具 | schemdraw/circuitikz 重画 |
| **全自动 AI 出 TikZ** | DeTikZify 8B 需量化；训练域不匹配 [待验证] | API + render-compare，人工验收 |
| **AI 超分"无中生有"地修好线稿** | 超分会编造边缘，等于伪造线宽/节点 | 线稿走矢量化，超分只用于灰度图 |
| **TikZ 代码又短又好看** | 追踪 → 每根线几十个贝塞尔控制点 | Path→Simplify + `--round-number 2`；或不用 TikZ |
| **完全避免人工** | 教材级质量需要语义理解 | 80% 图走脚本，20% 关键图人工 |

**两个风险提醒**

1. **SourceBook 仓库无 License 文件** —— 处理再分发的电子书有法律不确定性。内部自用无碍，公开发布前确认。
2. **GPL 传染性**：potrace / autotrace / svg2tikz 均为 GPL。独立命令行工具使用，产物（PDF/SVG/TikZ）不受 GPL 约束；若把代码链接进发布程序需注意。

## 八、本地实测结论（2026-10-07，8 张真实插图三轮对比）

对第一轮 MinerU 测试导出的 8 张插图（数字设计 RISC-V p.99-102，198 DPI 扫描），
用 `调研/vectorize_test.py`（第一轮）、`vectorize_test2.py`（第二轮）、`vectorize_test3.py`（第三轮）
实测了 5 条路线，对比图在 `调研/vectorize/compare/`：

| 路线 | 做法 | 结果 |
|---|---|---|
| A_direct（第一轮） | vtracer binary 直接矢量化 | 线条锐利但**笔画加肥**、小字母粘连走样 |
| B_binary（第一轮） | 背景除法+OTSU → vtracer | 更肥（OTSU 把抗锯齿灰边并入黑） |
| C_color（第二轮） | vtracer color 模式（保留灰度层） | **小字出现灰色重影**，显虚 |
| D_enh_color（第二轮） | CLAHE+unsharp → vtracer color | 同上，改善有限 |
| **E_potrace45/50（第三轮）** | **mkbitmap `-f 4 -s 3` → potrace** | **字形保持、细虚线连续、SVG 体积减半** ✓ |

**关键解释**：vtracer 直接在 200 DPI 原分辨率上做阈值/分层；potrace 链路的 `mkbitmap -s 3`
**先把图平滑放大 3 倍再阈值化**——边缘从"阶梯状像素一刀切"变成亚像素级平滑过渡，
这就是"字形不走样 + 线条不加肥"的根因。E45（-t 0.45）与 E50 差异微小，选 0.45（细节保留略多）。

**最终选定管线**（服务 tex 交付）：

```
MinerU PNG → mkbitmap -f 4 -s 3 -t 0.45 → (PBM) → potrace
   ├─ -b pdf → 插图交付（\includegraphics，LaTeX 原生）
   └─ -b svg → 预览 / 个别图转 TikZ 用
```

- 实测速度：~0.1 秒/张（8 张全量 1.6 秒），可全量批处理
- 风险更新：vtracer 不再采用；autotrace 中心线模式未实测（如未来对线宽有更高要求可补测）
